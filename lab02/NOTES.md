Различия между Git и GitHub:
Git — это распределённая система контроля версий (СКВ). Её основная задача — отслеживать изменения в коде проекта, сохранять историю этих изменений и позволять возвращаться к предыдущим версиям при необходимости. Git работает локально на компьютере разработчика: он фиксирует «снимки» состояния проекта (коммиты), позволяет создавать ветки для параллельной работы, объединять изменения от разных участников и разрешать конфликты. 
GitHub — это онлайн-платформа для хостинга Git-репозиториев. Она предоставляет не только хранилище кода, но и инструменты для совместной работы: систему отслеживания задач (issues), механизм pull request для предложения и обсуждения изменений, а также автоматизацию процессов (GitHub Actions)

Ветка:
Ветка в Git — это указатель (ссылка) на определённый коммит в истории проекта. Это не копия проекта и не отдельная ветка файлов, а именно метка, которая показывает, на какой именно «точке» в истории вы сейчас находитесь. 
Когда вы создаёте новую ветку (например, git branch new-feature), Git просто создаёт новый указатель с указанным именем и привязывает его к текущему коммиту. В этот момент ветка и основная ветка (обычно main или master) указывают на один и тот же коммит. 
По мере того как вы делаете новые коммиты в этой ветке (редактируете файлы, добавляете изменения, фиксируете их), указатель ветки автоматически сдвигается на новый коммит. Так формируется отдельная линия разработки. 
Слияние (merge). При слиянии Git находит общий предок веток и создаёт коммит слияния, который объединяет изменения из обеих веток. Если изменения пересекаются, возникают конфликты, которые нужно разрешить вручную.
